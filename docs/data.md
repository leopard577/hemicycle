# Data pipeline

`npm run data` runs `scripts/build-data.mjs`. It downloads every source, joins them, and writes one file per
page in `public/data/`: `deputies.json`, `senators.json`, `government.json` and `candidates.json`, each fetched by its page when it opens.
Nothing is cached between runs: each run downloads everything again (about 170 MB, almost all of it the HATVP
XML and the RNE).

## Layout

```
scripts/
  build-data.mjs   downloads every source in parallel, builds each page, writes public/data/<page>.json
  pay-scales.mjs   hand-maintained amounts: SMIC, deputies' and senators' pay scales, function allowances
  deputies.mjs     "Députés" page: loadDeputies() downloads the AN archive, buildDeputies() builds the dataset
  senators.mjs     "Sénateurs" page: loadSenators() downloads the Sénat sources, buildSenators() builds the dataset
  government.mjs   "Gouvernement" page: hand-maintained list from the Journal officiel decrees, buildGovernment()
  candidates.mjs   "Candidats" page: loadCandidates() downloads sponsorships and results, buildCandidates() adds the CNCCFP accounts
  lib/
    util.mjs       asArray, text, download, parseCsv, parseQuotedCsv, frToIso, name normalisation and matching
    hatvp.mjs      loadHatvp(): downloads liste.csv and the XML once, returns (officials, mandate) => Map
    rne.mjs        loadRne(): downloads the RNE once, returns (officials) => Map
```

Sources shared by several pages (HATVP, RNE) are downloaded once. Each page module exports a `load…()`
function that downloads its own source and a `build…(source, { hatvpFor, rneFor })` function that returns the
page's dataset, `{ payScales, groups, members }` for a chamber. A new page adds one module and one `write()` call in
`build-data.mjs`. `hatvpFor` takes the mandate to look for: its `mandateType` (`type_mandat` in `liste.csv`),
`isDeclaration(general)`, which recognises its declarations of interests in the XML, and `originId()`, which
computes `id_origine` from the page's own id (null when the HATVP has none). `hatvpFor.rows` exposes the raw
`liste.csv` rows.

The output files are git-ignored. In production it is regenerated by the GitHub Pages workflow
(`.github/workflows/deploy.yml`) on every push to `main` and every Monday. Not keeping it in git means no
frozen copy of personal data stays in the history, and the deployed site is never staler than a week.

## Sources

| Source | URL | Used for |
| --- | --- | --- |
| AN, active deputies, mandates and bodies (AMO10, JSON zip) | `data.assemblee-nationale.fr/static/openData/repository/17/amo/deputes_actifs_mandats_actifs_organes/AMO10_deputes_actifs_mandats_actifs_organes.json.zip` | Deputies, groups and colours, committees, functions, seat number, staff list, contact details |
| HATVP list of declarations (CSV, `;`-separated) | `www.hatvp.fr/livraison/opendata/liste.csv` | Which declarations each deputy filed, with dates and publication status |
| HATVP consolidated declarations (XML, ~81 MB) | `www.hatvp.fr/livraison/merge/declarations.xml` | Content of declarations of interests: income, holdings |
| RNE, Répertoire national des élus (CSV, `;`-separated, ~75 MB) | resolved at build time from `www.data.gouv.fr/api/1/datasets/repertoire-national-des-elus-1/` (file URLs change on every update) | Local mandates currently held by each deputy (`localMandates`) |
| AN fiche de synthèse n° 7 (January 2026) | `assemblee-nationale.fr/dyn/synthese/deputes-groupes-parlementaires/la-situation-materielle-du-depute` | Pay scales, hard-coded in `scripts/pay-scales.mjs` |

Photos are not downloaded. The dataset only stores their URL on assemblee-nationale.fr.

## Steps

1. **AN archive** (`deputies.mjs`). Unzip in memory and keep actors that hold an active `ASSEMBLEE`
   mandate in legislature 17. For each one, pick:
   - the most recent active `GP` mandate, which gives the political group;
   - the `PARPOL` mandate, which gives the party used for public funding;
   - the active `COMPER` mandates, which give the standing committees;
   - email, website and X handle from `adresses`.
2. **Special allowances** (`specialAllowances` in `deputies.mjs`). Each active mandate is checked against
   `DEPUTY_SPECIAL_ALLOWANCES` (`pay-scales.mjs`), keyed by organ type, organ and role: President of the Assemblée, quaestor, vice-president or
   secretary of the Bureau, chair of a standing committee, general rapporteur, chair of the OPECST. The
   "Bureau d'âge" is deliberately ignored.
3. **HATVP** (`loadHatvp` in `lib/hatvp.mjs`). Download the CSV and the XML, keep only deputy declarations, then
   match them to AN deputies (see below).
4. **RNE** (`loadRne` in `lib/rne.mjs`). Download the municipal, district, intercommunal, departmental, regional,
   territorial-assembly and European files. A row is assigned to a deputy on exact birth date plus a shared
   surname token; the first name only breaks ties between deputies born the same day. Community councillor
   rows are kept but not counted as a separate mandate in the UI, since they follow from a municipal seat.
5. **Other HATVP functions.** Every row of `liste.csv` for the same person shares `url_dossier`. Rows whose
   `type_mandat` is not `depute` become `hatvp.otherMandates` (senator, mayor, EPCI president…).
6. **Sort and write.** Groups are ordered left to right according to `GROUP_ORDER`. Deputies are sorted by
   group, then by real seat number, so each group forms a contiguous wedge of the chart.

## Senators (`senators.mjs`)

| Source | URL | Used for |
| --- | --- | --- |
| Sénat, current senators (JSON used by senat.fr) | `www.senat.fr/api-senat/senateurs.json` | Who sits, group, real seat number (`siege`), constituency, renewal series, photo and page URLs, X handle |
| `ODSEN_GENERAL` (CSV) | `data.senat.fr/data/senateurs/ODSEN_GENERAL.csv` | Birth date, profession, e-mail, Bureau role |
| `ODSEN_ELUSEN` | same folder | Current term (no end date) and its start date |
| `ODSEN_CUR_COMS` | same folder | Current committees and roles (chair, general rapporteur…) |
| `ODSEN_CUR_OFFDEL` | same folder | Current delegations and offices (delegation chairs, OPECST) |
| `ODSEN_HISTOGROUPES` | same folder | Group presidents (current membership and function with no end date) |
| Sénat pages on the allowance, expenses and staff | see `senatorPayScales.sources` | Pay scales, hard-coded in `scripts/pay-scales.mjs` |

The `data.senat.fr` exports are **comma-separated, quoted and cp1252-encoded**, with `%` comment lines at the
top: read them with `parseQuotedCsv` after decoding with `TextDecoder('windows-1252')`.

- **Function allowances** (`SENATOR_SPECIAL_ALLOWANCES`): each rule names the file its role is read from
  (`bureau`, `group`, `committee`, `delegation`, `opecst`) and a regular expression on the role. Only
  permanent-committee chairs count as "présidents de commission". The dedicated expense advances (IT, Paris
  lodging, representation) are not counted in the seat cost; the panel notes say so.
- **HATVP**: `type_mandat=senateur`, `id_origine` is the Sénat matricule (`21077M`), so the join is exact; the
  XML mandate label is `Sénateur`. Coverage is low after a renewal: in October 2026, 167 of 348 have
  declaration content, and 179 of the 181 others took office on 1 October 2026 and are still within the
  two-month deadline. The panel then says "Déclaration attendue d'ici le …" instead of flagging a missing
  declaration.
- **Groups**: the Sénat publishes no colour. `GROUP_COLORS` in `senators.mjs` is chosen by the app; the order
  is `GROUP_ORDER` (group codes, left to right). A new group code must be added to both.
- **Quirks**: a senator without a seat (a minister) has `siege: 0`, stored as `seat: null`; `ODSEN_CUR_COMS`
  lists a committee named `Aucune` for senators outside any committee, which is dropped; e-mails marked
  `Non public` become `null`. The build fails if a senator has no current term.

## Government (`government.mjs`)

No official source publishes the composition of the Government as data with appointment dates: the AN open
data tracks only ministers who were deputies and stopped at January 2024, and the HATVP lists a minister only
once their declaration is filed. `MEMBERS` and `DEPARTURES` in `government.mjs` are therefore **copied by hand
from the decrees** published in the Journal officiel (`DECREES`, each with its Légifrance link), plus the
Conseil constitutionnel decision for the President's term.

- **Updating it**: at every reshuffle, add the new decree to `DECREES`, then add, move or end members. The
  build fails when `liste.csv` lists a current member of the Government (a `gouvernement` row whose `qualite`
  does not start with "Ancien") missing from `MEMBERS`.
- **Dates**: `startDate` is the first appointment in the current Government (cost counter, filing deadline);
  `roleStart` and `roleDecree` record a later change of title (David Amiel, Maud Bregeon…).
- **Order and teams**: `MEMBERS` follows the decree, which is the protocol order; the page seats members around
  the council table in that order. `reportsTo` names, by surname, the Prime Minister or minister(s) a minister
  delegate is placed with ("auprès de"); the build resolves it to ids and fails on an unknown name. Keep it in
  step with the wording of `role` at every reshuffle.
- **Pay** (`governmentPayScales` in `pay-scales.mjs`) is computed from decree no. 2012-983 rather than typed
  in: 1.4 × the "hors échelle" average for ministers and ministers delegate, 2 × the average + 5% for the
  President and the Prime Minister, plus 3% residence allowance and 25% function allowance. The average is the
  deputies' base allowance (same definition), so both move together. Cabinets, the Élysée budget, official
  housing and cars are not counted.
- **HATVP**: `liste.csv` has no `id_origine` for these offices, so the join is on surname and first name. The
  XML declarations of interests of ministers have type `DI` (not `DIA`) and `codTypeMandatFichier` =
  `gouvernement`; the CSV calls them `di`/`dim`. The President's 2022 declaration is listed but its content is
  not in the XML. Liste.csv and the decrees give no birth date: it is taken from the matched declaration
  (`declarantBirthDate`), which also lets the RNE match.
- **Photos**: never from hatvp.fr: its legal notice requires prior permission for its photos. A member who was
  a deputy in the 17th legislature gets the AN photo: `loadAssemblyActors()` reads the AMO50 archive (every
  actor of the legislature, former deputies included), downloaded with `downloadResumable` because the AN
  server often cuts it. A current or former senator gets the senat.fr photo, whose URL is rebuilt from names
  and matricule (`senatorPhoto`, `ODSEN_GENERAL`). Both are matched on names and birth date. In October 2026,
  21 of 36 have a photo; the others show their initials. `liste.csv` cannot help: it only keeps current
  mandates.

## Candidates (`candidates.mjs`)

The 2022 presidential election. Candidates are not `Official`s: standing for office is not holding one, and the
page uses neither the HATVP nor the RNE.

| Source | URL | Used for |
| --- | --- | --- |
| Conseil constitutionnel, sponsorships (CSV, UTF-8, `;`, quoted) | `static.data.gouv.fr/…/20220307-183308/parrainagestotal.csv` | Count per candidate, by sponsor office (`SPONSOR_OFFICES`) and department |
| Ministère de l'Intérieur, final national results of each round (cp1252, `;`) | `static.data.gouv.fr/…/resultats-par-niveau-fe-t1-france-entiere.txt`, `…-t2-…` | Candidates, ballot board number, sex, votes and share of votes cast; turnout |
| CNCCFP decisions of 14 December 2022 (JO of 27 January and 24 February 2023) | `www.cnccfp.fr/wp-content/uploads/2023/02/cnccfp-decisions-presidentielle-2022.pdf` | `ACCOUNTS`, hand-copied |
| Conseil constitutionnel and CNCCFP pages on the refund rules | see `presidentialFunding2022.sources` | Ceilings, refund rates, advance (`pay-scales.mjs`) |

- **Join**: the results file gives surname and first name, the sponsorship file "SURNAME First name"; both are
  normalised with `normalizeName`. The build fails if a candidate has no sponsorship or no account.
- **Results file layout**: one data row; after the turnout columns, a block of 7 columns per candidate
  (`N°Panneau;Sexe;Nom;Prénom;Voix;% Voix/Ins;% Voix/Exp`), while the header names only the first block.
- **Accounts**: `retained` is the CNCCFP's "montants retenus", `entitlement` the lowest of the refund cap, the
  refundable spending and the personal contribution net of surplus, `irregular` the spending found irregular
  (not refundable), `penalty` the reduction under art. L. 52-11-1, `refund` the amount owed by the State
  (article 2, the 200,000 euro advance included). The build checks `entitlement ≤ cap` and
  `entitlement − irregular − penalty = refund`. Jean Lassalle's article 1 contradicts its own table; the table is
  kept.
- **Press net worth** (`PRESS_NET_WORTH`): each candidate's net worth as reported by franceinfo/AFP on 8 March
  2022, rounded, copied from the article and cited on the page. The asset declarations were public from 8 March
  to 13 April 2022 only, then removed by the HATVP; this is the one exception to the asset declaration rule,
  decided by the project owner. Nothing else from those declarations is stored. The page compares them with
  `householdWealth` (`pay-scales.mjs`): the median and mean net wealth of households early 2024, INSEE enquête
  Histoire de vie et Patrimoine 2023-2024 (148,100 and 325,000 euros, per household, not per person). Update it
  with each new survey.
- **`election.datasets`** holds the data.gouv.fr page of each downloaded file; the page links to them.
- **Sponsors are never named**, and neither are the 52 people who received sponsorships without being on the
  official list: only counts are stored.

## Matching HATVP records to deputies

The two HATVP files are matched differently.

**`liste.csv`** carries `id_origine`, the numeric AN id (`PA841729` becomes `841729`), so the join is
exact. When `id_origine` is empty (one case today, Élisabeth Borne), the script falls back to the
normalised surname and first name.

**`declarations.xml`** has no AN id. Only declarations of type `DIA` whose mandate type is `Député` are
used. For each person (surname, first name, birth date) the most recent one is kept: a modifying
declaration (DIAM) restates the full content. They are then matched in three passes, from the safest rule
to the loosest. A declaration is assigned at most once, and a rule only applies when it finds exactly one
candidate.

1. Same birth date, and both surname and first name match.
2. Same birth date and same surname, but a different first name (a usual first name, e.g. Jimmy vs
   Jean-Michel).
3. Same surname and first name, but a different birth date (a typo on one side, e.g. day and month
   swapped).

A name "matches" when the two share at least one token after normalisation: accents and punctuation
removed, upper case, the full string also counts as a token. Particles (`LE`, `DE`, `DU`, `LA`…) are not
tokens on their own: before October 2026 they were, and six elected women whose name starts with "Le" or
"de La" were given the local mandates of a namesake born the same day (Marine Le Pen with a councillor seat in
Auray, Anne Le Hénanff with one in Poligné…). This handles usual and compound surnames
(`LUCAS` vs `Lucas-Lundy`, `KBIDI` vs `K/Bidi`) and declarations where surname and first name were
swapped. Requiring the first name in rules 1 and 3 avoids false positives between two people born on the
same day, and assigning each declaration only once keeps namesakes apart, such as the two Alexandra
Martin.

Current coverage: all 574 deputies have at least one listed declaration, and 538 have declaration-of-interests
content. The other 36 are "filed, publication pending" or "being processed" at the HATVP.

## Output schema

The types are in `src/types.ts`; keep them in sync with the scripts. Overview:

```ts
ChamberDataset<Deputy | Senator> {
  generatedAt: string            // ISO timestamp
  payScales: PayScales           // pay scales, identical for every member; `sources: { label, url }[]`
  groups: Group[]                // ordered left → right
  members: T[]                   // ordered by group, then seat number
}

Official {                       // fields shared by every page
  id, honorific, firstName, lastName, birthDate: "YYYY-MM-DD", photo, startDate
  hatvp: {
    page: string | null                 // the person's page on hatvp.fr
    declarations: { type, label, filedAt, publishedAt, status }[]  // newest first
    interests: Interests | null         // null = no published content available
    otherMandates: { type, institution, role, lastFiledAt }[]
  }
  localMandates: { type, label, place, role, start, roleStart, updatedAt }[]   // RNE
}

Parliamentarian extends Official {
  groupId, groupRole, seat, committees[], email, twitter, profession, sortName
  specialAllowances: { label, body, amount }[]   // gross per month, €
}

Deputy extends Parliamentarian {
  id: "PA841729", department, departmentCode, constituency, party, website, staffCount, ...
}

Senator extends Parliamentarian {
  id: "21077M", constituency, constituencyCode, series, bureauRole, affiliation, senatPage
}

Interests {
  filedAt, amended
  jobs | mandates | consulting | directorships: Income[] | null
  holdings: Holding[] | null
}
```

**`null` and `[]` mean different things in `Interests`.** `[]` means the deputy declared "néant" (none);
`null` means the section is missing from the declaration. The UI shows them differently.

Amounts in `Income.amounts` are yearly amounts as declared. `grossNet` says whether they are gross or net.
A field the HATVP redacts entirely (`[Données non publiées]`) becomes `null`. A partly redacted field
(`SCI [Données non publiées]`, about 3,500 cases, mostly company names) is kept verbatim, marker included:
the HATVP's [legal notice](https://www.hatvp.fr/mentions-legales/) requires reproduced information to stay
intact, and stripping the marker would turn the redacted name into "SCI".

`status` keeps the raw HATVP value: `Livrée`, `Déclaration déposée - publication à venir`,
`Déclaration déposée - publication en préfecture à venir` or `En cours`. `src/lib/declarations.ts` turns it
into a label.

## Derived indicators (front end)

`src/lib/money.ts` computes everything shown in the "Cumuls" tab, the alerts and the hemicycle readings.
Nothing is stored in the dataset.

- **Seat cost**: gross allowance + special allowances + expense allowance + staff credit, per month, from
  `payScales`. The live counter prorates it from `startDate`. The staff credit is a ceiling, not spending.
- **Income lines**: each `Income` of the declaration of interests is classified (deputy mandate, European
  Parliament, Senate, local mandate, job, consulting, board). A line is "in progress" when it has no end
  date or ended after `startDate`. Lines in different sections with the same latest amount are counted once
  (a company often appears both as a job and as a board seat).
- **Alerts** only state dated facts: executive local function in the RNE for more than 30 days of overlap
  at the RNE file date; RNE mandate older than the declaration but not found in it (keyword or place-name
  match on the free-text title); RNE mandate started after the last DIA/DIAM and more than two months ago;
  entry declarations filed after two months plus a week of tolerance. The wording must stay factual.

## Asset declarations (DSP)

The content of asset declarations (`dsp`, `dspm`, `dspfm`) is never stored or displayed, for anyone. For
parliamentarians it can only be consulted in a prefecture, and publishing it is punishable under article
LO 135-2 of the electoral code. The HATVP does publish the asset declarations of members of the Government
and of the President, and the XML contains those of ministers (type `DSP`), but the app keeps the same rule
for them: `isDeclaration()` only accepts declarations of interests, so the asset content is parsed with the
rest of the file and dropped. Only the rows of `liste.csv` (type, dates, status) are kept. **Do not add the
content of these declarations, even if a source for it turns up** (the only exception is the press-reported net
worth of the 2022 presidential candidates, see Candidates), unless the project owner decides
otherwise after a legal check.

## Updating pay scales

`deputyPayScales` and `DEPUTY_SPECIAL_ALLOWANCES` in `scripts/pay-scales.mjs` are copied by hand from the AN
fiche n° 7, and `minimumWage` (the SMIC) from service-public.gouv.fr.
When the Assemblée revises them, update both, along with `miseAJour`, and rerun `npm run data`. The fiche
does not say how several special allowances combine, so the UI simply adds them up and shows a warning if
a deputy has more than one.

## Limitations

- **Self-declared data.** Income and holdings are what the deputy declared. The HATVP redacts some
  fields, such as company names.
- **Declaration content may lag behind.** It is the latest declaration present in the XML. A declaration
  can show as "Livrée" in the CSV before the XML includes it; the UI then says so.
- **Staff counts.** `staffCount` counts the staff listed by the AN. The list is undated and may
  include successive employees, so it can exceed the limit of 5 simultaneous staff.
- **Group order.** `GROUP_ORDER` in `deputies.mjs` is maintained by hand. A new group abbreviation is
  placed at the far right until it is added there.
- **RNE lag.** The RNE is published every few months. A mandate or function that ended since may still
  appear, which is why alerts quote the RNE file date.
- **Free-text titles.** Declared mandates are free text ("CONSEILLER DEPARTEMENATL", "présidente CD
  Lozere"). Matching them to RNE mandates is heuristic: check a flagged deputy by hand before quoting it.
- **Missing deputies.** Vacant seats are not drawn, which is why there are 574 seats rather than 577.
